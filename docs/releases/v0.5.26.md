shell-lsp 0.5.26 models Makefile rules written with variables the way make
reads them: recipes replaced by a later rule and target-specific variables
inherited by prerequisites are now followed through variable targets and
static pattern rules.

## Fixes

- Makefiles:
  - A recipe make never runs because a later rule replaces it is no longer
    checked when the targets are written with variables or the rules are
    static pattern rules. A rule counts as replaced only when every one of
    its targets is, and a name listed twice in one rule is no longer reported
    as replacing its own recipe.
    ([#108](https://github.com/stubbedev/shell-lsp/issues/108))
  - Target-specific variables pass to prerequisites when the target or the
    prerequisite is written with a variable, and from every target of a rule,
    not only the first.
    ([#107](https://github.com/stubbedev/shell-lsp/issues/107))
  - A variable defined only for a parent target is found in a
    prerequisite's recipe instead of being reported as unknown, and go to
    definition reaches it. Global definitions still take precedence.

## Install

Release binaries for Linux and Windows (amd64, arm64) and macOS (arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.26` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.26.vsix` below. Editor setup:
[the documentation](https://stubbedev.github.io/shell-lsp/editors/).
