shell-lsp 0.5.4 adds the checks that a comparison with other linters showed
missing, fixes a dozen places where the parser disagreed with the shells it
models, and holds both the linter and the parser to real-world code in CI.

## New checks

On by default:

- SC3003: `$'...'` strings in POSIX sh and dash, which leave them undefined.
- SC2180: a second subscript on a bash array, as in `${a[1][2]}`; bash arrays
  have one dimension.
- SC2330: a glob on the right of `==` in busybox `[[ ]]`, which busybox
  expands against file names before comparing.
- SL1006: a sensitive path made writable by every user, such as
  `chmod -R 777 ~/.ssh` or `chmod o+w /etc/sudoers`.

Optional, enabled by name through `lint.optional` or a `# shellcheck enable=`
directive; the first three are part of the `strict` profile:

- SL2012 `require-test-grouping`: `&&` and `||` mixed in `[[ ]]` without
  parentheses.
- SL2013 `check-relative-sources`: a file sourced by a path relative to
  wherever the script is run from, rather than to the script itself.
- SL2014 `require-local-variables`: a function assigns a variable it did not
  declare local.
- SL2015 `avoid-global-reassignment`: a global variable is given a new value.
- SL4001 to SL4007, `google-shebang`, `google-file-header`, `google-todo`,
  `google-function-comments`, `google-comment-sections`,
  `google-script-length` and `google-main`: the rules of the Google Shell
  Style Guide, with the guide's own thresholds.

## Fixes

- `[[ ]]` groups `&&` above `||`, and `!` applies to the operand after it
  only, as every shell evaluates them; the parser had given `&&` and `||` the
  same precedence.
- SC2026 is no longer reported after a `$'...'` string.
- Call hierarchy keeps each definition of a function defined twice apart:
  preparing on a definition returns that one, on a call every definition it
  could reach, and outgoing calls follow the definition asked about.
- The parser accepts what the shells accept and rejects what they reject,
  found by comparing it with `-n` of each shell over thousands of scripts:
  - zsh: the length prefix with further operators (`${#x%c}`), empty
    alternatives in case pattern groups (`(|l)server)`), conditions that
    modules provide (`[[ $s -pcre-match p ]]`), arrays assigned before a
    command, a subscript after a subscript (`${a[2][1]}`), and the keys of
    the special associative arrays (`$+functions[_omz::x]`).
  - ksh93, as ksh93u+m 1.0.10 parses it: the `;` that starts a statement,
    redirections before subshells, arithmetic commands, declarations and
    `name()` functions, and errors for `&>>`, `;;&`, NUL bytes and a newline
    after `));`.
  - bash: `let x=1 # comment` is a comment, not a syntax error, and a second
    array subscript parses, so SC2180 can name it.
  - A here-document started inside a subshell is read after the subshell's
    first newline, as every shell does, not after its `)`.
  - A backslash inside a `printf` format directive is an invalid directive.
- Inputs found by fuzzing no longer crash the linter: a here-document that is
  never closed and whose delimiter ends in a backslash, among others.

## Checked in CI

- The linter is compared with ShellCheck 0.11.0, code by code, over 88 pinned
  public repositories (about 7,300 scripts), and the parser with bash, dash,
  zsh, ksh93u+m, mksh and BusyBox over the same corpus and the Oils spec
  tests. Any change from the committed baselines fails CI; see
  [docs/corpus.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/corpus.md).
- The whole test suite runs in the Nix dev shell with those shells and
  ShellCheck present, so the fixture oracle and the parser's real-shell tests
  no longer skip; the suite also runs on macOS.
- Every fuzz target is fuzzed each night, and pull requests get a benchmark
  comparison with their base.
- [CLEAN_ROOM.md](https://github.com/stubbedev/shell-lsp/blob/main/CLEAN_ROOM.md)
  states what may and may not inform the code.

## Install

Release binaries for Linux, macOS and Windows (amd64, arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.4` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.4.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
