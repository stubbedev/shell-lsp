shell-lsp 0.5.15 adds native Nix support. It is meant to replace nixd or nil
on its own: navigation, completion, rename, formatting and linting for Nix,
and everything shell-lsp does for shell in the shell written inside Nix.

## Nix

- Definition, references, rename, hover, completion, signature help, document
  and workspace symbols, call hierarchy, inlay hints, semantic tokens, folding
  and code actions work across a flake's files, for single flakes, flake-parts
  and dendritic trees, with no evaluator.
- `lib.x` is read from the locked nixpkgs source. Flake inputs show their locked
  revision and date, link to their forge, and have an "Update input" action.
- Formatting matches `nixfmt` byte for byte on the files we compared: 5,500 of
  5,500 nixpkgs files, and 5,110 of 5,112 files mangled first to test the
  formatter's own layout decisions.
- The `SL8xxx` rules cover what statix and deadnix find, compared on 45,209
  nixpkgs files, and honour `statix.toml`. Most have fixes, and fix-all applies
  them.
- `shellLsp.nix.evaluate`, off by default, adds option and package answers from
  a real `nix eval`, in the background and cached on disk. It needs Nix 2.24,
  Lix 2.95 or Determinate Nix on Nix 2.24, or newer. Answers appear as they
  arrive and never block a request.
- A rename that would break evaluation, such as a module argument, is refused,
  and the refusal says what would break and where.

## Languages inside Nix

- Shell in `writeShellScript`, `runCommand`, phases and more gets findings,
  fixes, tokens, hover, navigation and completion. A `${pkg}/bin/x` resolves to
  the program, and a string passed to a wrapper in another file is proven
  through the call.
- Justfiles, Makefiles, Dockerfiles and Nix written from Nix get the same
  features, including `home.file."x.nix".text` and `writeText "x.nix"`. Quick
  fixes apply to the Nix string and re-escape what they write.
- `$name` in a jq or awk program follows `--arg` and `-v`, in Nix and in a plain
  shell script.

## Memory and speed

Measured on an 89-file flake with `cmd/nixparity`:

| | shell-lsp | nil | nixd |
|---|---|---|---|
| Peak memory | 78 MiB | 380 MiB | 576 MiB |
| Idle memory | 62 MiB | 58 MiB | 562 MiB |

Definition and hover answer in about 75 µs at the median, and completion in
about 185 µs. Editing also allocates less per keystroke in plain shell: about
103,000 objects, down from 125,000.

## Fixes

- `check -` can lint standard input as Nix, a Makefile, a justfile or a
  Dockerfile, chosen by `--filename`.
- The "nix develop" lens opens a terminal and enters the shell, instead of
  exiting at once.
- Semantic tokens no longer drop shell tokens from non-primary dialects in Make,
  just and Docker files.
- `$$` in a quoted heredoc is no longer treated as a stand-in in plain scripts.

## Known limits

- A justfile or Makefile in a `.nix` string written from Nix gets no fixes for
  recipe or target names.
- Nix itself has to be installed for `nix.evaluate` and for reading inputs not
  yet in the store.

## Install

Release binaries for Linux and Windows (amd64, arm64) and macOS (arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.15` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.15.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
