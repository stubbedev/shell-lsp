shell-lsp 0.5.5 explains the shell's own string tools: the glob patterns,
parameter expansions and `=~` regular expressions that scripts use instead of
starting sed, grep, awk, basename or tr. Hover takes them apart and, where the
values are known, shows what they produce; new checks catch the options they
need and the escapes that do not work, and suggest the expansion where a
command does the same job.

## Hover

- Glob patterns are explained piece by piece wherever they appear: in
  `${x#…}`, `${x%%…}`, `${x//…/…}`, zsh's `${a:#…}` and subscript searches,
  `[[ … == … ]]`, `case` items and file names. That covers POSIX wildcards and
  bracket expressions; bash and ksh extended globs, ksh93's `{n,m}(…)`,
  non-greedy `*-(…)` and `~(i)`, `~(E)` and `~(F)` options; and zsh's groups,
  numeric ranges such as `<1-10>`, `^`, `~`, `#` and `##`, globbing flags such
  as `(#i)`, `(#b)` and `(#s)`, and glob qualifiers such as `(.om[1,3]N)`.
  Captured groups are numbered as they land in `$match`.
- The regular expression of `[[ … =~ … ]]` is explained the same way,
  following each shell's quoting rules for what reaches the regex engine.
- A parameter expansion shows its result when the values it reads come from
  literal assignments earlier in the file, naming the lines they came from:
  `${f:t:r}` with `f=archive.tar.gz` gives `archive.tar`. The evaluator is
  tested against bash, zsh and ksh93 themselves and covers zsh's flags,
  modifiers, nested expansions and `$match`, and bash's case conversions,
  slices and the `&` of `patsub_replacement`. Where a value or a result is
  not certain, it shows nothing.
- When the tested value is known, `[[ … == … ]]`, `case` items and `=~` say
  whether they match, and `=~` shows what `BASH_REMATCH` or `$match` holds.
- Hover points out operators whose shell option the file never enables, and
  what a file name pattern does when nothing matches.

## Completion and highlighting

- zsh globbing flags complete after `(#`, and glob qualifiers after `(#q`.
- Pattern operators, bracket expressions, numeric ranges, globbing flags,
  glob qualifiers and the parts of regular expressions are semantic tokens.

## New checks

On by default:

- SL2016: a pattern operator whose shell option is never turned on, such as
  zsh's `(#i)` without `extendedglob`, bash's `!(…)` without `extglob` (a
  syntax error, also when `shopt -s extglob` is on the same line or in the
  same function), or `**/` without `globstar`.
- SL2017: `$match`, `$MATCH` or `BASH_REMATCH` read when nothing in the file
  sets it.
- SL2018: an unquoted `&` in a bash replacement, which bash 5.2 turned into
  the matched text.
- SL2019: a zsh pattern that zsh rejects as bad.
- SL2020: `basename`, `dirname` (in zsh), `pwd`, `tr`, `cut` or
  `echo … | grep -q` started for what a parameter expansion or `[[ ]]` does,
  with a fix that rewrites it.
- SL2022: `\d` in a `=~` regular expression, which POSIX regular expressions
  read as the letter `d`, and bash's `\w` or `\s` written directly in the
  word, where the backslash only quotes the letter.

Optional, enabled with `useless-use-of-cat` like SC2002:

- SL2021: `$(cat file)` where `$(<file)` reads the file without `cat`.

SC2001 now also applies to zsh, and offers a fix that rewrites a literal
`sed 's/old/new/'` as `${var//old/new}`.

## Fixes

- A `source` path built from a loop variable or from a `local` declared
  without a value is no longer resolved through an older assignment of the
  same name.

## Install

Release binaries for Linux, macOS and Windows (amd64, arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.5` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.5.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
