shell-lsp 0.5.25 fixes a hang that 0.5.24 brought into the zsh parser, checks
justfile attributes and format strings the way just 1.58 does, and corrects
what the linter assumes about ksh93, mksh, busybox sh and dash. Every
per-shell fact the linter relies on is now checked against the real shells.

## Fixes

- In a zsh file, a redirect whose word ends in `}` followed by more input
  that is not valid, such as `>0}}})`, made the server loop forever on the
  syntax error. Upgrade from 0.5.24.
- SC2311 is reported only in bash and busybox sh, the shells that clear
  `set -e` inside `$(…)`. zsh, ksh93, mksh and dash keep it, so they no longer
  get the warning, and busybox sh is no longer told to use `shopt`.
  ([#98](https://github.com/stubbedev/shell-lsp/issues/98))
- ksh93 has no `local`: "Declare as local" is no longer offered there, and
  SL2014 asks for `typeset` in `function` functions as before. mksh has
  `local` in both function forms and is now checked like bash.
- mksh runs the last stage of a pipeline in a subshell, unlike ksh93, and
  only mksh runs code in arithmetic subscripts, so SL1003 now covers bash and
  mksh instead of bash and ksh.
- ksh93 and busybox sh match a quoted `=~` pattern as a regex, so SC2076 no
  longer fires there; busybox sh supports `=~`, so SC3015 no longer does
  either.
- Associative arrays: bash 5.1 and later read `m=(k v)` as key value pairs,
  so SC2190 now says bash before 5.1 rejects it; zsh's bare elements after a
  `[key]=` are reported. New SL2023 reports a `[key]=value` element inside a
  key value list, and SL2024 an odd number of elements.
  ([#99](https://github.com/stubbedev/shell-lsp/issues/99),
  [#100](https://github.com/stubbedev/shell-lsp/issues/100))
- Fifteen SC3xxx portability checks named the wrong shells, mostly busybox
  constructs it does support (process substitution, `++`, `**`, `let`,
  `base#n`, `>&file`, descriptors above 9, bare `read`), and `exec --` was
  reported. `$'...'`, `[^a]` and `set -o pipefail` stay reported in dash with
  "not supported in dash before 0.5.13", since Debian and Ubuntu ship 0.5.12.
  ([#101](https://github.com/stubbedev/shell-lsp/issues/101))
- `set` and `exec` hover, completion and option tracking know the options of
  bash, zsh, ksh93 and mksh as those shells have them, and keep ksh93 and mksh
  apart; zsh `set -G`/`set -y` and ksh93 `set -G` now turn on nullglob,
  shwordsplit and globstar.
- Justfiles:
  - A function call with whitespace before its arguments, such as
    `uppercase ("a")`, is read as a call, as just reads it.
  - Format strings are lexed as just lexes them, so an unterminated `f"`
    is reported on its own line, and `import x "…"` and `{{ if … { 'c' } }}}`
    are accepted.
  - Attributes are checked by just 1.58's rules: `[arg]` keys, values,
    `long`/`short`, `flag`, `min`/`max`, patterns and duplicates, which
    attributes each item may carry, compile-time constants in settings,
    `[doc]` and `[arg]`, and `[cache]` only on script recipes.
    ([#104](https://github.com/stubbedev/shell-lsp/issues/104))
  - A dependency on an alias is reported, as just resolves dependencies to
    recipes only; `[continue]` takes any number of signals.
  - The formatter writes attribute arguments and orders `[arg]` attributes
    as `just --fmt` does.
- Makefiles: a recipe make never runs because every target of its rule
  already exists, such as `./`, no longer has its references checked as if it
  ran; `.PHONY`, `FORCE` prerequisites and `./x`-style target names are
  handled as make handles them.
- The Nix formatter matches nixfmt on lambda chains with set patterns,
  comments after a colon, blank lines and `@` aliases, and is idempotent on
  inputs where it was not.
  ([#105](https://github.com/stubbedev/shell-lsp/issues/105))

## Editors

- The server registers for settings changes itself, so clients that support
  dynamic registration report them without configuration. The VS Code
  extension moves to vscode-languageclient 11.

## Development

- The per-shell facts, the SC3xxx shell sets and the `set`/`exec` data are
  checked against bash, zsh, dash, ksh93, mksh and busybox sh at pinned
  versions in CI.
- The Dockerfile oracle is BuildKit 0.35.1, Dependabot and govulncheck cover
  its module, and `just sync-flake` refreshes its vendorHash. Grype and
  dependency review fail on high-severity findings.

## Install

Release binaries for Linux and Windows (amd64, arm64) and macOS (arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.25` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.25.vsix` below. Editor setup:
[the documentation](https://stubbedev.github.io/shell-lsp/editors/).
