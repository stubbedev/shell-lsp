shell-lsp 0.5.1 polishes the shell-in-other-files support of 0.5.0 and fixes
a few long-standing findings.

## Fixes

- SC2221 and SC2222 name the line of the other `case` pattern; they named
  the line after it.
- A function that only a `trap` runs, as in `trap 'cleanup' EXIT`, is no
  longer reported as never invoked (SC2329) when the script ends in `exit`.
- In Makefiles and justfiles, a variable changed on one recipe line and read
  on the next is reported as changed in a line that runs in a shell of its
  own, instead of in a `( )` group that does not appear in the file.
- An unclosed `$(` in a recipe line (`echo $$(date`) is reported at the `$(`,
  instead of at the start of the line as a missing `)`.
- Makefile recipes honour `.SHELLFLAGS` (`-e`, `-u`, `-o pipefail`) and the
  `-e` a `.POSIX` target implies, so checks that `set -e` makes moot, such as
  SC2164, are not reported there.
- Running Bats tests and the hover of a command without a manual page search
  the `PATH` the server was started with.

## Install

Release binaries for Linux, macOS and Windows (amd64, arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.1` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.1.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
