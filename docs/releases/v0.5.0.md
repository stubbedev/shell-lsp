shell-lsp 0.5.0 lints the shell that lives inside other files: Makefile and
justfile recipes and the shell strings of Nix expressions are checked in
place, in the editor and with `shell-lsp check`, and every answer and fix is
given in the file's own positions and syntax.

## Highlights

- **Makefiles**: recipe lines are linted as the shell `SHELL` names (`sh`
  without it), each line in a shell of its own as make runs it, so a variable
  or `cd` that does not reach the next line is reported and a syntax error
  stays on its line. `$$` is the shell's `$`, make expansions such as `$(CC)`
  and `$@` are unknown values, and fixes write `$` back as `$$`.
  `.RECIPEPREFIX`, `.ONESHELL`, inline `; recipes` and `define` blocks are
  understood.
- **justfiles**: recipe bodies are linted line by line, or as one script for
  shebang and `[script]` recipes, with the shell from the shebang,
  `[script(...)]`, `set script-interpreter` or `set shell`. `{{...}}` is an
  unknown value, exported variables and `$` parameters count as set, and
  fixes escape `{{` as `{{{{`.
- **Nix**: derivation phases and hooks, `runCommand`, the `writeShellScript`,
  `writeShellApplication`, `writeBash`, `writeDash` and `writeScript`
  writers, `shellHook` and systemd unit scripts are linted, also through
  `lib.optionalString`, `lib.mkIf` and `+`. Phases run as stdenv runs them,
  `writeShellApplication` keeps its strict mode and `excludeShellChecks`, and
  a `/* bash */` comment opts any other string in.

Hover, completion, navigation, rename and quick fixes work inside the shell
of these files; outside it, and on host expansions, they find nothing. They
are not formatted, and their shell is decided by the file rather than by a
`# shellcheck shell=` directive. The VS Code extension attaches to the
`makefile`, `just` and `nix` languages; other editors add those file types
([docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md)).
`shell-lsp check` finds these files when it walks a directory, and
`shell-lsp fmt` skips them. Details are in
[Shell in other files](https://github.com/stubbedev/shell-lsp/blob/main/README.md#shell-in-other-files).

## Fixes

- A `let` whose quoted expression is empty, as in an unclosed `let "`, no
  longer crashes the linter.
- An unclosed command substitution inside an array (`a=($(cmd`) no longer
  crashes the linter while building the SC2207 fix.
- Completing a word that holds a NUL byte offers no paths instead of failing
  the completion request.

## Install

Release binaries for Linux, macOS and Windows (amd64, arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.0` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.0.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).

## Known limitations

- Shell that Nix assembles across `${...}`, such as `case` patterns built by
  `lib.optionalString`, cannot be checked without evaluating the Nix code and
  may be reported as a syntax error.
- A file is checked as one shell: the family most of its scripts use, widened
  to bash when bash scripts share it with sh ones; scripts in another family
  are left out.
