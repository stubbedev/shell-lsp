shell-lsp 0.5.9 understands justfiles, Makefiles and Dockerfiles as languages
of their own, not only the shell inside them, so it is the one server an
editor needs for these files. Every check was compared with the tool that
reads the file: just 1.58, GNU Make 4.4 and BuildKit 0.34.

## Features

- **Justfiles and Makefiles natively.** Syntax errors, unknown recipes,
  targets, variables, functions, settings and attributes, wrong argument
  counts, duplicates, circular dependencies and recursive variables, unused
  parameters and variables, and missing `import`, `mod` and `include` files,
  under the `SL5` and `SL6` codes of
  [docs/rules.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/rules.md).
  Definition, references, rename, hover, completion, signature help, inlay
  hints, call hierarchy, quick fixes, document and workspace symbols,
  folding, semantic tokens, links and selection ranges work across
  `import`, `mod` and `include`, and from the shell of a recipe to the just
  or make variable it reads.
- **Dockerfiles natively.** BuildKit's parser errors and build checks under
  `SL7` codes, honouring `# check=skip=` and `# check=error=true`;
  navigation and rename for stages and build arguments, also from the shell
  of a `RUN`; hover and completion for instructions, flags, stages and
  variables; links on the files `COPY` and `ADD` take. The shell of every
  `RUN`, `CMD`, `ENTRYPOINT`, `HEALTHCHECK CMD` and heredoc is linted as the
  shell `SHELL` names in the stage or its base stages.
- **Each recipe as its own shell.** A justfile, Makefile, Dockerfile or Nix
  file is no longer linted as one shell: each recipe is checked as the shell
  its shebang, `[script(...)]`, `set shell`, `SHELL` or target-specific
  `SHELL` names, so a bashism in a plain recipe is reported even when another
  recipe is bash. The VS Code status bar shows the shell of the recipe under
  the cursor.
- **Formatting.** Justfiles are formatted like `just --fmt`; Makefiles get
  consistent spacing around operators and rule colons, without changing the
  database `make -p` prints.
- **Run lenses and tasks.** Recipes and targets get "▶ Run" lenses, and
  recipes with parameters a "▶ Run…" lens that asks for the arguments in
  VS Code, which also offers every recipe and target as a task.
- The VS Code extension starts for Dockerfiles too.

## Install

Release binaries for Linux, macOS and Windows (amd64, arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.9` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.9.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
