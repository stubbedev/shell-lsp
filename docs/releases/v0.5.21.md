shell-lsp 0.5.21 makes the Nix formatter settle on its first pass for the inputs
the nightly fuzzing found, and clears the dependency advisories the security
scans reported.

## Fixes

- Formatting a Nix file twice no longer changes it the second time. Several
  layouts only came out right on a second run: a commented expression in
  parentheses such as `f (# c` followed by `{ a = 1; })`, a pattern lambda whose
  chain ends on a blank line, a set pattern too wide for the line such as
  `{ aVeryLongName }: { ... }`, and a lambda chain broken before its colon. The
  first pass now prints what the second pass settles on. Where nixfmt 1.5.0 is
  stable, the output is unchanged; on these inputs nixfmt itself is not stable.
- A tab before an interpolation in a string no longer makes the interpolation
  break onto its own lines. Only spaces set it apart, as in nixfmt.
- Commented indented strings in parentheses, such as `x: (/* nix */ ''...'')`,
  stay on the colon's line as nixfmt keeps them.

## Security

- The Dockerfile support's BuildKit oracle moves to patched
  `klauspost/compress` (GO-2026-6865) and `golang.org/x/net` (GO-2026-6860,
  GO-2026-6866), and to the `golang.org/x/crypto` commit that removes the
  unmaintained openpgp packages (GO-2026-5932).
- The documentation site pins vite 6.4.5 and esbuild 0.25, clearing their
  advisories.

## Install

Release binaries for Linux and Windows (amd64, arm64) and macOS (arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.21` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.21.vsix` below. Editor setup:
[the documentation](https://stubbedev.github.io/shell-lsp/editors/).
