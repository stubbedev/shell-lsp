shell-lsp 0.5.8 recognises justfiles, Makefiles and Nix files by their name
whatever language the editor gives them. In VS Code, a justfile that a
`files.associations` entry or another extension maps to Shell Script was
linted as one bash script: every `env('X', 'y')` was a syntax error,
`[private]` a command and `set shell := [...]` an SC2121, where Neovim, which
sends the `just` file type, showed only the findings in the recipes.

## Fixes

- A file named `justfile`, `Justfile`, `JUSTFILE`, `.justfile` or `*.just`,
  `Makefile`, `makefile`, `GNUmakefile`, `*.mk` or `*.mak`, or `*.nix` is
  analysed as that file, with only the shell in its recipes and strings
  checked, also when the editor opens it as `shellscript`. The language
  identifiers `just`, `makefile`, `make` and `nix` still make any other file
  one.

## Install

Release binaries for Linux, macOS and Windows (amd64, arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.8` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.8.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
