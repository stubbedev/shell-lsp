shell-lsp 0.5.24 reads braces in zsh the way zsh does, stops reporting a
false error on Makefiles whose rule targets substitute to nothing, and fixes
the quoting hover shows for ksh and zsh. The nightly fuzz run now compares
with the real just, make, BuildKit, nix and shells, which is how these were
found.

## Fixes

- In zsh, an unquoted `}` that ends a word closes a block, unless a `{`
  earlier in the word is still open. `echo a}` is now reported as the syntax
  error zsh makes of it, and `{ echo a}` is a complete block.
  ([#95](https://github.com/stubbedev/shell-lsp/issues/95))
- In zsh, a `{` glued to the first word of a command opens a block, so
  `{echo hi}` and `f() {echo hi}` are read as zsh runs them instead of as a
  command named `{echo`.
  ([#95](https://github.com/stubbedev/shell-lsp/issues/95))
- In zsh, an unquoted `${...}` ends at the `}` that balances its braces, so
  `${x/{f}/Y}` replaces `{f}` and `${y//{Q}/1 2}` is one word. Inside double
  quotes it still ends at the first `}`, as in zsh.
  ([#95](https://github.com/stubbedev/shell-lsp/issues/95))
- A Makefile rule whose targets come from a substitution reference that
  expands to nothing, such as `$(OBJS:.c=.o)` with `OBJS` unset, no longer has
  its recipe checked as if make ran it, which gave a false SL6012 error.
  ([#94](https://github.com/stubbedev/shell-lsp/issues/94))
- Hover on a ksh pattern no longer shows a `\x` escape that ksh93 reads
  together with the hex digits after it, and on a zsh pattern it quotes a word
  that ends in `}`.
  ([#93](https://github.com/stubbedev/shell-lsp/issues/93))

## Development

- `REQUIRE_REFERENCES=1` makes every test that compares with a reference tool
  fail instead of skipping when the tool is missing or of another version; it
  replaces `REQUIRE_SHELLS`. `nix develop .#fuzz` provides the references the
  fuzz targets need. ([#92](https://github.com/stubbedev/shell-lsp/issues/92))

## Install

Release binaries for Linux and Windows (amd64, arm64) and macOS (arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.24` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.24.vsix` below. Editor setup:
[the documentation](https://stubbedev.github.io/shell-lsp/editors/).
