shell-lsp 0.5.28 carries shell options from Dockerfile `SHELL`, justfile
`set shell` and `env` shebangs into the shell checks, honours buildx bake and
compose named contexts in the Dockerfile checks, reads git's ignore
configuration and repository layout as git does, and parses more of zsh's
short forms.

## Changes

- Shell options from the interpreter's arguments:
  - A Dockerfile `SHELL ["/bin/bash", "-euo", "pipefail", "-c"]` turns on
    errexit, nounset and pipefail for every later `RUN`, heredocs included,
    and child stages inherit it, so SC2164, SC2103 and the other
    option-dependent checks no longer run as if the options were off.
  - A justfile recipe takes its options from `set shell`, just's default
    `sh -cu`, `script-interpreter` or its own shebang.
  - `#!/usr/bin/env -S bash -e`, `SHELL ["/usr/bin/env", "bash", "-e", "-c"]`
    and busybox are resolved to the interpreter and its flags. Script
    shebang options other than errexit, such as nounset and pipefail, now
    apply too.
- Dockerfiles:
  - Named contexts from docker-bake HCL and JSON files and from compose
    `build.additional_contexts` are honoured: a `FROM` or `COPY --from`
    naming one is not reported by DL3006 or SL7005, unless the mapped
    `docker-image://` value itself has no tag. Bake files are found across
    the git repository, with `${VAR}` defaults, `inherits` and `cwd://`
    paths; the search stops after 20,000 directories and says so.
  - DL3020 and DL3010 look at the source after unquoting and expansion, so
    a quoted URL or git ref is no longer told to use `COPY`, and a quoted
    archive is no longer missed. Quoted `COPY` sources link to the right
    file.
  - `check` and the editor apply the lint profile to hadolint findings the
    same way.
- The YAML reader accepts anchors, aliases, `<<` merge keys and compose's
  `!reset` and `!override` tags, with alias expansion bounded.
- `check` and `fmt` skip explicitly named files of other languages (`.hcl`,
  `.yaml`, `.py`, …) as directory mode does, so
  `git diff --name-only | xargs shell-lsp check` reports only shell files.
  `--shell` and `-ln` still force them through.
- `.envrc` is checked as bash and `*.zsh-theme` as zsh. Files sourced by
  convention, such as themes and `*.plugin.zsh`, no longer have their
  functions reported as unused.
- Git: the workspace walk and bake discovery read `.git/info/exclude` and
  `core.excludesFile` from the system, global, repository, worktree and
  command-line configs with `includeIf`, find repositories as git does
  (symlinked `.git`, bare repositories, `GIT_CEILING_DIRECTORIES`,
  `core.worktree`, symbolic refs), and `check` and `fmt` honour `GIT_DIR`,
  `GIT_WORK_TREE` and `GIT_COMMON_DIR`.
- A full refresh from the client drops every file-backed cache, including
  shellcheckrc, editorconfig, statix and flake.lock settings.

## Fixes

- zsh: the short `if` and loop forms with an empty or one-sublist body, a
  lone `;` where a newline may stand, a list ending at `&&` or `||`, and
  `;` inside array literals now parse as zsh parses them. A `do` swallowed
  by a `for` word list gets a hint at the stray `done`.
- A loop iteration left without a name by a parse error no longer panics
  on position queries.
- justfiles, found by the fuzzers:
  - A variable defined in terms of itself through user-defined functions,
    such as `A := A()` with `A() := A`, is reported as just reports it.
  - An `[arg]` attribute naming an undefined argument is reported even when
    its `pattern=` is not a valid regex.

## Install

Release binaries for Linux and Windows (amd64, arm64) and macOS (arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.28` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.28.vsix` below. Editor setup:
[the documentation](https://stubbedev.github.io/shell-lsp/editors/).
