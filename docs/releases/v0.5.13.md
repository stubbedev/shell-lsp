shell-lsp 0.5.13 fixes crashes, a hang and formatter instabilities that the
nightly fuzzers found on malformed input, and drops the Intel macOS build,
which nixpkgs no longer supports.

## Fixes

- The linter no longer panics on unclosed zsh subscripts such as `$A[0[$.`
  or `0$A[0[0[A(00 .` (SC2250, SC1037), or on an arithmetic expansion that
  error recovery closes in the middle of a word, such as `$((##0##0`.
- SC1037 no longer reads a naked arithmetic subscript such as `0[i]` as the
  positional parameter `$0`.
- The parser no longer hangs on invalid UTF-8 right after a subscript inside
  `${…}`, or panics on a here-document whose word crosses a newline, such as
  `<<$A[` in zsh.
- An unclosed here-document, and other recovered parses, no longer give
  commands spans past the end of the file.
- The justfile formatter refuses, naming the line, to reorder repeated
  `[arg]` attributes that `just --fmt` would reorder again on the next run,
  and justfile comments that error recovery read twice no longer crash
  folding.
- The Makefile formatter keeps `&:` attached to a lone target that names a
  make keyword, so `vpath&:` stays a rule instead of becoming a `vpath`
  directive.

## Platforms

- macOS release binaries are arm64 only; there is no darwin/amd64 binary and
  the VS Code extension says so on an Intel Mac.
- The Nix flake is built on flake-parts, and `x86_64-darwin` is no longer
  among its systems. Output names are unchanged.

## Install

Release binaries for Linux and Windows (amd64, arm64) and macOS (arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.13` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.13.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
