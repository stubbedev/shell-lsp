shell-lsp 0.5.6 keeps what one shell does out of the others. Every Makefile
and justfile recipe line, every shebang recipe and every Nix shell string runs
in a shell of its own, and 0.5.5's hover, highlighting and pattern checks
treated the whole file as one: an assignment or a `shopt` in one recipe
changed what was shown and reported in every other. Subshells, command and
process substitutions, background jobs and pipelines in ordinary scripts had
the same problem.

## Fixes

- Hover no longer evaluates an expansion or a `[[ … ]]` test from an
  assignment made in another recipe, or in a subshell that has already exited:
  with `x=a.b` in one recipe, `${x%.*}` in the next shows no result, and
  after `x=1; (x=2)`, `$x` is `1`.
- Shell options apply only in the shell that sets them and the subshells it
  starts. `shopt -s nullglob` in one recipe no longer tells hover that every
  other recipe's file names expand to nothing, and `set -o pipefail`,
  `set -e`, `shopt -s lastpipe`, `inherit_errexit` and the glob options no
  longer change the checks in recipes, subshells or substitutions that do not
  run with them.
- SL2016 no longer reports an extended glob in a recipe or Nix string that
  turns on `extglob` on a line of its own above it. It does report one whose
  recipe never turns the option on, even when another recipe does, and one
  after a `shopt -s extglob` that ran in a subshell. In justfiles and Nix
  strings its fix, which adds the `shopt` line, is now offered too.
- A `source` path is no longer resolved through an assignment made in a
  subshell that has exited.

## Install

Release binaries for Linux, macOS and Windows (amd64, arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.6` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.6.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
