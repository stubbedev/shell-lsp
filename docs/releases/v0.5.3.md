shell-lsp 0.5.3 makes the editor and `shell-lsp check` report the same
findings, fixes a run of checks that each kept their own, drifting copy of what
a command or a shell accepts, and corrects what hover and completion say about
`set` options and `$0` in each shell.

## The editor and `check` agree

- The editor now builds its lint settings exactly as `shell-lsp check` does:
  `shell=` in the nearest `.shellcheckrc` chooses the shell, and SC2148 reports
  a script that names no shell, in the editor as on the command line.
- A code range such as `disable=SC2000-SC2086` in `.shellcheckrc` or
  `--exclude` leaves out its end, as it already did in a directive and as
  ShellCheck does, so SC2086 is still reported.

## Fixes

- A shebang that names a shell with its version, such as `bash5`, `bash-5.2`,
  `zsh-5.9` or `dash-0.5.12`, chooses that shell; a `zsh-5.9` script was
  linted as bash. SC1008 now reports exactly the interpreters that choose no
  shell, including names that only start like one, such as `bashful`.
- A quoted command name counts like an unquoted one in every check, so
  `"exec" server; true` gets SC2093.
- `printf -vNAME` and `read -aNAME` define their variable when the name is
  attached to the option.
- SL1002 finds the `-c` script after shell options that take a value, as in
  `sh -o errexit -c "$input"`.
- Each command's options come from one grammar, checked against the real
  tools: SC2232 knows `sudo -D`, `doas` and `run0`; SC2267 reads `xargs`
  options as GNU and BusyBox `xargs` do, with `-e` taking its end-of-file
  string only when attached and long options such as `--null` understood;
  and SC2156 also covers `sudo zsh -c` after `-exec`.
- Builtin flags in sh, dash and busybox are checked against the same data that
  hover uses, corrected against dash 0.5.13 and busybox 1.37: SC3045 reports
  `hash -v` in dash and `ulimit -p` in busybox, and accepts busybox's `read -t`
  and `export -n`.
- SC2209 and SC2238 know every POSIX utility, including `id`, `true`, `ps` and
  `pwd`.
- The "Ignore for this command" quick fix adds the code to a directive above
  the command in any spelling, and never adds a code that is already disabled.
- Completion works after an escaped backslash, as in `\\$x`.
- The outline names the file in `source -- lib.sh` instead of `--`.
- Hover on `<<#` here-documents in ksh, and semantic tokens for the last line
  of a here-document that runs to the end of the file.
- Hover and completion for `set` letters follow the shell: in zsh `-F` is
  `noglob` and `-f`, `-h` and `-k` are not `noglob`, `hashall` and `keyword`;
  dash's `-E`, `-V` and `-I`, busybox's `-E` and `-I`, and ksh's
  `braceexpand`, `histexpand`, `keyword` and `trackall` are described.
- Hover on `$0` inside a function says what it holds in that shell: the script
  name in bash and sh, the function's name in zsh and in ksh functions
  defined with `function`.
- Hover and completion agree on what a command argument is: `shopt -o` offers
  `set -o` names, and `kill` arguments are no longer read as trap conditions.
- Signature help highlights parameters correctly for clients that negotiated
  UTF-8 positions.
- `shell-lsp fmt -p` parses exactly like `-ln=posix`, and `check` and `fmt`
  read a file named twice only once.
- A just recipe with a shebang and only comments no longer reports a syntax
  error.
- `shellLsp.runBats` on a document that is not a Bats file returns an error
  instead of running it.
- A JSON-RPC message with neither a method nor an id gets an invalid-request
  error instead of being dropped.

## For client authors

`shellLsp/documentDialect` now answers `selectable`; `directive` and `dialects`
are present only when it is `true`, and it is `false` for shell in Makefiles,
justfiles and Nix files, whose host decides the shell. `source` can also be
`shellcheckrc`. See the README's Dialects section.

## VS Code

Fix All, Run Bats File and Choose the Shell to Lint As are offered for
Makefiles, justfiles and Nix files too. In those files Choose the Shell to Lint
As explains where the file sets its shell, and the status bar warns with the
reason when the server cannot say which shell a document uses.

## Install

Release binaries for Linux, macOS and Windows (amd64, arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.3` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.3.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
