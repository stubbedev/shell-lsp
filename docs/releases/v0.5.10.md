shell-lsp 0.5.10 checks Dockerfiles with Hadolint's rules and reads its
pragmas and `.hadolint.yaml`, so a project that runs Hadolint can drop it and
keep its configuration. Every rule was compared with Hadolint 2.14.

## Features

- **Hadolint's rules for Dockerfiles**, under its `DL` codes: pinned versions
  and caches for apt, apk, yum, dnf, microdnf, zypper, pip, npm, gem, yarn and
  go, image tags and trusted registries, the last `USER`, `COPY` and `ADD`,
  `EXPOSE` ports, `ENV`, pipes without `pipefail`, consecutive `RUN`s and
  label schemas. Commands are read the way the tools read them, through
  `sudo`, `env` and `xargs`, with each tool's options, and words take the
  values `ARG` and `ENV` give them. Findings sit on the word they are about,
  such as the unpinned package. Problems BuildKit's checks already report
  keep their `SL7` code, and the `DL` code stands for them in pragmas and
  configuration. Every rule is listed in
  [docs/checks.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/checks.md#dl1001).
- **`# hadolint` pragmas.** `ignore=` for the next instruction, its shell
  findings included, `global ignore=` for the file, and `shell=` to lint later
  `RUN`s as another shell.
- **`.hadolint.yaml`.** The nearest `.hadolint.yaml` or `.hadolint.yml` above
  the Dockerfile, then Hadolint's user locations: `ignored`, `override`,
  `trustedRegistries`, `label-schema`, `strict-labels` and
  `disable-ignore-pragma`. A broken file is reported with its line and column
  instead of being applied. Where shell-lsp deliberately differs from
  Hadolint is described in
  [docs/hadolint.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/hadolint.md).

## Fixes

- `Dockerfile.dockerignore` and other ignore files named after a Dockerfile
  are no longer linted as Dockerfiles.
- `MAINTAINER` with spaces in its value is no longer a syntax error.
- `HEALTHCHECK` durations without a unit or below a millisecond, and retries
  that are negative or no whole number, are reported as the errors BuildKit
  makes them.
- Completing a command no longer scans the whole script for an enclosing
  `case`, which took tens of milliseconds in long scripts; the `case` comes
  from the syntax tree, which also offers its values before the first
  pattern (`case $1 in st`) and leaves out the patterns already written.
- Hover and completion no longer crash at the end of `case x in (`.

## Install

Release binaries for Linux, macOS and Windows (amd64, arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.10` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.10.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
