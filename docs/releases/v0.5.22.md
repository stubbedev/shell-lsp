shell-lsp 0.5.22 adds sed script completion and checks, shows comments as
documentation for variables, keeps man-page text intact in hover and
completion, lets Makefile exports cross include boundaries, and fixes the
bugs the nightly fuzzing found. Each release now measures its own
performance figures in CI.

## Features

- Inline sed scripts get completion: sed commands with their documentation
  wherever a command can start, regex operators spelled for basic or `-E`/`-r`
  syntax inside an address or `s` pattern, and the script's labels after `b`,
  `t` and `T`. ([#88](https://github.com/stubbedev/shell-lsp/issues/88))
- The sed checks now follow GNU sed 4.10, verified by an agreement test: label
  ends, `r`/`R` without a file, `{p}p`, invalid intervals and back-references,
  unmatched parentheses and quantifiers after anchors in extended syntax.
  `\{,3\}` and counts with leading zeros are no longer reported.
- Hovering a variable shows the comment lines directly above its assignment, or
  a comment at the end of the assignment's line, as its documentation; variable
  completion shows it too. ([#87](https://github.com/stubbedev/shell-lsp/issues/87))
- Names a Makefile or justfile exports count as set in the recipes of the files
  it includes and of the files that include it.
  ([#81](https://github.com/stubbedev/shell-lsp/issues/81))
- A macro the Makefile only ever sets to `@`, `-`, `+` or nothing, such as
  `Q = @`, is read as recipe prefix flags even when a space separates it from
  the command. ([#80](https://github.com/stubbedev/shell-lsp/issues/80))
- The release workflow measures the README's performance figures on the
  release and adds them to these notes.
  ([#83](https://github.com/stubbedev/shell-lsp/issues/83))

## Fixes

- Man-page text is escaped for Markdown, so placeholders such as
  `<new-branch>` no longer vanish from hover and completion documentation, and
  bold and italic text keep their fonts. Examples and paragraphs nested under an
  option are now part of its documentation.
  ([#84](https://github.com/stubbedev/shell-lsp/issues/84))
- A Makefile rule whose targets come from a variable that expands to nothing,
  such as `OBJS ?= ${CFLAGS}`, no longer has its recipe checked as if make ran
  it, which gave false errors such as "variable `CC` depends on itself".
- The Nix formatter keeps an application, operation, `if` or simple lambda on
  one line when a comment ends the file, as nixfmt does, and formats such files
  the same way on every pass.
- The Nix formatter keeps `'') (args)` together after a lambda chain whose body
  starts with a comment, as nixfmt does. All nixpkgs files format exactly as
  nixfmt 1.5.0 formats them again.

## Security

- The Dockerfile support's BuildKit oracle moves to OpenTelemetry 1.47.0
  (GHSA-q7gw-24fr-5p69).

## Install

Release binaries for Linux and Windows (amd64, arm64) and macOS (arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.22` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.22.vsix` below. Editor setup:
[the documentation](https://stubbedev.github.io/shell-lsp/editors/).
