shell-lsp 0.5.2 adds two checks for bugs that neither ShellCheck nor earlier
releases noticed, and drops a set of findings that were wrong for scripts that
read variables by name, complete commands or colour their output.

## New checks

- SL2010: an escape that produces a NUL byte (`\x00`, `\0`, `\u0000`, `\c@`)
  cuts a `$'...'` string short, since shell strings cannot hold one;
  `$'a\x00b'` is just `a`. zsh, whose strings can, is not checked.
- SL2011: an arithmetic `&&` whose bounds on one variable leave no value, as
  in `(( cp >= 0xd800 && cp <= 0xdff ))`, where the upper bound lost a digit.

## Fixes

- A variable read by name counts as read for SC2034: the target of a nameref,
  `${!name}`, `${!prefix@}`, `declare -p "$name"`, and names passed to a
  function that reads its argument that way, also from a sourced file. A
  script that reads variables named on its command line or in its input gets
  no SC2034 at all, since any variable may be read.
- An assignment or `for` loop after `local x` in a function belongs to that
  local, in checks as in hover, definition and completion; it was taken for
  the global `x`.
- SC1010 reports a glued `done`, `fi` or `esac` only inside the loop, `if` or
  `case` it could close, so `echo done` is fine.
- SC1003 accepts single-quoted strings that are only backslashes or end in a
  doubled one, such as `tr '\' '/'` and `printf '\e]0;%s\e\\'`.
- SC2059 accepts a printf format held in a variable that is only ever built
  from fixed text, such as `"$COLOR%15s$RST"`.
- SC2207 and SC2046 accept `compgen` actions that print only names or a fixed
  word list, as in `COMPREPLY=($(compgen -v -- "$cur"))`, and SC2207 accepts
  `pgrep` as SC2046 already did.
- SL1003 no longer treats what `printf -v` writes with only numeric
  conversions, such as `printf -v code '%d' "'$char"`, as outside data.

## Install

Release binaries for Linux, macOS and Windows (amd64, arm64) with
`SHA256SUMS` are attached below. Alternatively
`go install github.com/stubbedev/shell-lsp@v0.5.2` or
`nix profile install github:stubbedev/shell-lsp`. For VS Code, install the
Shell LSP extension, or `shell-lsp-0.5.2.vsix` below. Editor setup:
[docs/editors.md](https://github.com/stubbedev/shell-lsp/blob/main/docs/editors.md).
